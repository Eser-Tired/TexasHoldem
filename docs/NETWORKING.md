# 局域网房间设计

## 连接与生命周期

使用 Godot ENet 高层多人 API，默认监听 UDP 24680。自动加载节点 `/root/LanRoom` 在所有实例中路径一致，负责 RPC。房主同时也是玩家，不需要独立服务器。客户端使用 IP 和端口加入；房间容量 2–4 人，至少两人且全部准备后开局。

状态依次为 `menu`、`connecting`、`lobby`、`playing`。连接最多等待 8 秒。双方连接握手携带协议版本，房主拒绝不同版本、满员和已开始的房间。开局后拒绝新连接。

客户端可以准备 / 取消准备；房主默认准备。仅房主可以开始游戏、开始下一手和重置筹码。每次开局以已登记的玩家创建实际 2–4 人牌桌，不补充电脑。

## 权威牌局

房主的 `PokerTable` 保存牌堆、所有底牌、随机源、轮次和筹码，是唯一能推进游戏的对象。客户端使用 `PokerView` 显示快照，不在本地发牌、算结果或自行改变筹码。

请求下注时传递动作、金额、当前手数和状态版本。房主用真实 RPC 发送者 ID 对照玩家座位，校验当前行动者、版本、合法动作、剩余筹码与最小加注。重复请求和上一状态的迟到请求无法再次下注。客户端在等待确认时临时禁用操作按钮。

每次合法状态变更递增版本并按可靠有序 RPC 同步。下一手与重新开局继续递增版本，不因手数重置而接受旧请求。

## 信息隔离

`snapshot_for(viewer, revision)` 为每位玩家独立构造快照。该玩家旋转至视图的座位 0，庄家、盲注、行动者和赢家索引同时旋转。UI 在两人桌将对手放在正上方；三人桌使用左右两侧；四人桌使用三处对手座位。

快照只包含接收者的真实底牌、公共牌、筹码、行动记录与公开状态。对手未摊牌的底牌替换为 `[-1, -1]`；正常摊牌仅揭示未弃牌玩家；未跟注获胜不会揭示对手牌。牌堆、随机源和服务器内部行动队列不被序列化。房主的 UI 同样使用自己的过滤视图，完整数据只保存在权威牌局中。

联机整局在只有一名玩家有筹码时结束，房主或任意玩家出局不会结束其他人的牌局。出局玩家不会收到新底牌，但可以继续观看。

## 离线处理

房主离开：所有客户端回到大厅，并显示连接中断提示。

其他玩家离开或连接中断：结束当前对局，移除该玩家，剩余玩家回到房间；清除当前牌局与准备状态，重新允许加入。下一次准备开局重置筹码。这一版本不保存或恢复中断的牌局，也不迁移房主。

ENet 对端使用 2–6 秒的失联检测参数。主动离开会关闭 peer；关闭窗口或机器断网后，由底层 ENet 检测并触发同一离线流程。

## 验证

- 保留原有 500 手随机对局与 60 手电脑策略测试。
- 2–4 人牌局单元测试：筹码守恒、盲注顺序、按接收者旋转、底牌隔离、摊牌与出局观战。
- 多进程通信测试：2、3、4 个 Godot 实例通过真实 ENet socket，使用实际大厅和按钮完成三手牌（正常下注、弃牌、全下）；检查结算、越权 / 过期 / 超额操作拒绝、离开与房主关闭。
- 房间准入测试：满员、未准备、取消准备、开局后连接超时、版本不一致、断线后再加入、关闭房间、错误地址与取消连接。

这些测试使用本机回环网络；跨电脑网络取决于局域网互通和系统防火墙设置。使用相同项目版本、同一网络和匹配端口进行实际联机。

Godot API 参考：[高层多人游戏](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html)、[ENetMultiplayerPeer](https://docs.godotengine.org/en/stable/classes/class_enetmultiplayerpeer.html)。
